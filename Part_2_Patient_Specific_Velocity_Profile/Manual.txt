# Patient-Specific Inlet Velocity Profile Extraction and Application Manual

## Supporting Files

The workflow includes a **Supporting Files** folder containing the intermediate files generated by the scripts and used by subsequent scripts.

These files allow the different steps of the workflow to pass their results to the next step. Each script uses the required input files from this folder and produces the corresponding output files needed for the following step.

The main files generated throughout the workflow are listed below:

```text
1_cap_coor.txt
3_cap_coor_mri.txt
4_cap_coor_mri_scaled.txt
5_coor_vel_grid.txt
6_coor_vel_GOI.txt
7_coor_vel_grid_time
8_coor_vel_grid_time
10_Coor_Cap_interpolated_timesteps.txt
11_Cap_interpolated_timesteps_step_1.txt
12_Cap_interpolated_timesteps_step_2.txt
13_Cap_interpolated_timesteps_step_3.txt
14_bc_interpolated.txt
15_bc_interpolated_cm.txt
16_bc_interpolated_cm_corrected.txt
17_bc_complete_interpolation_correction.txt
```

Not every file is a final result. Some files are **intermediate or supporting files** that store the results of a specific processing step and provide the input required by the next script.

The user does not normally need to modify these files manually. They are generated and used automatically as part of the workflow.

---

# Step 0. Workflow Overview

This workflow converts **4D Flow MRI velocity data** into a **patient-specific, time-dependent velocity inlet boundary condition** for a CFD simulation.

The main processing steps are:

```text
4D Flow MRI data
      ↓
Step 1. Prepare CFD inlet-cap coordinates
      ↓
Step 2. Extract MRI velocity data
      ↓
Step 3. Map MRI velocities onto the CFD inlet cap
      ↓
Step 4. Return coordinates to the original CFD system
      ↓
Step 5. Create and correct the CFD boundary-condition file
      ↓
Step 6. Optional temporal interpolation
      ↓
Patient-specific CFD inlet velocity profile
```

Steps 1–5 are required to generate the patient-specific inlet profile.

**Step 6 is optional** and is used only when additional temporal interpolation and smoothing of the inlet profile are required.

---

# Step 1. Preparation of the CFD Cap Coordinates

The first step prepares the CFD inlet-cap coordinates so that they can be matched with the MRI coordinate system.

### 1.1 Inspect the CFD inlet cap

Load and inspect the `bct.vtp` file to identify the geometry and spatial points of the CFD inlet cap.

### 1.2 Extract the cap coordinates

Extract the coordinates of all points on the CFD inlet cap and save them for further processing.

### 1.3 Align the coordinate origins

Identify the CFD point corresponding to the MRI origin `(0, 0, 0)`.

Subtract the coordinates of this reference point from all CFD inlet-cap points so that the CFD and MRI coordinate origins are aligned.

### 1.4 Transform to the MRI coordinate system

Apply the required coordinate transformation to express the CFD inlet-cap coordinates in the MRI coordinate system.

### 1.5 Match the MRI scale

Scale the transformed coordinates so that their dimensions match the MRI coordinate system and grid dimensions.

### 1.6 Save the prepared coordinates

Save the final scaled coordinates for use in Step 3.

**Final result:**  
The CFD inlet-cap coordinates are expressed in the **MRI coordinate system and scale**, ready for mapping the MRI velocity data onto the CFD inlet cap.

---

# Step 2. MRI Grid Data Extraction

This step extracts the MRI velocity data required for the inlet boundary condition.

### 2.1 Extract the MRI velocity grid

Load the 4D Flow MRI velocity data from the HDF5 file.

### 2.2 Define the Grid of Interest (GOI)

Define a **Grid of Interest (GOI)** around the region where the flow of interest enters the CFD domain.

The GOI is manually selected to enclose the MRI region surrounding the CFD inlet.

### 2.3 Reduce the amount of data

Use the GOI to limit the amount of MRI data that must be processed.

Since only the velocity at the CFD inlet cap is required, there is no need to process the entire MRI velocity volume.

### 2.4 Extract the velocity data

For each MRI timestep, extract the three velocity components:

```text
U   V   W
```

at every grid point within the GOI.

### 2.5 Repeat for the complete cardiac cycle

Repeat the extraction for all timesteps to obtain the MRI velocity data throughout the cardiac cycle.

### 2.6 Save the extracted data

Save the GOI coordinates and velocity components in TXT files for the following processing steps.

**Final result:**  
The MRI velocity data surrounding the CFD inlet cap are extracted for the complete cardiac cycle, while unnecessary regions of the MRI volume are excluded from processing.

---

# Step 3. Spatial Interpolation

This step transfers the MRI velocity data from the MRI grid onto the CFD inlet-cap points.

### 3.1 Load the CFD inlet-cap coordinates

Load:

```text
4_cap_coor_mri_scaled.txt
```

These are the CFD inlet-cap coordinates prepared in Step 1 and expressed in the MRI coordinate system and scale.

They are used as the **target points** for the interpolation.

### 3.2 Load the MRI velocity data

Load the MRI velocity data from:

```text
8_coor_vel_grid_time
```

The data contain the MRI coordinates and the `U`, `V`, and `W` velocity components for all timesteps.

### 3.3 Define the interpolation points

The MRI GOI points are used as the **input points**, while the CFD inlet-cap points are used as the **target points**.

This transfers the MRI velocity data onto the CFD inlet cap.

### 3.4 Interpolate the velocity components

Interpolate `U`, `V`, and `W` separately.

Linear interpolation is applied first.

### 3.5 Fill missing values

If linear interpolation cannot provide a value at a CFD inlet-cap point, use nearest-neighbour interpolation for that point.

This ensures that every CFD inlet point receives a velocity value.

### 3.6 Repeat for all timesteps

Repeat the interpolation for every timestep of the cardiac cycle.

The CFD inlet-cap coordinates remain fixed, while the velocity values change with time.

### 3.7 Save the interpolated data

Save the resulting data as:

```text
10_Coor_Cap_interpolated_timesteps.txt
```

**Final result:**  
The MRI velocity field has been mapped onto the CFD inlet cap for every timestep of the cardiac cycle.

---

# Step 4. Return to the Original CFD Coordinates

After spatial interpolation, the inlet-cap coordinates are still expressed in the scaled MRI coordinate system.

This step reverses the coordinate transformations applied in Step 1 and returns the coordinates to the original CFD coordinate system.

The velocity values are **not modified** during this step.

## 4.1 Return to the Original MRI Scale

### Load the interpolated data

Load:

```text
10_Coor_Cap_interpolated_timesteps.txt
```

### Load the original MRI coordinates

Load:

```text
3_cap_coor_mri.txt
```

and determine the original MRI coordinate limits required to reverse the scaling.

### Reverse the X and Y scaling

Convert the scaled X and Y coordinates back to their original MRI values.

### Reverse the Z scaling

Divide the Z coordinates by the scaling factor used in Step 1.

### Keep the velocity unchanged

The `U`, `V`, and `W` velocity components remain unchanged.

### Save the result

Save:

```text
11_Cap_interpolated_timesteps_step_1.txt
```

---

## 4.2 Return to the MRI Coordinate System

### Load the descaled data

Load:

```text
11_Cap_interpolated_timesteps_step_1.txt
```

### Apply the inverse coordinate transformation

Apply:

```text
X_new = -Y
Y_new =  X
Z_new = -Z
```

This reverses the coordinate transformation applied in Step 1.

### Keep the velocity unchanged

The `U`, `V`, and `W` components remain unchanged.

### Save the result

Save:

```text
12_Cap_interpolated_timesteps_step_2.txt
```

---

## 4.3 Restore the Original CFD Coordinate System

### Load the transformed data

Load:

```text
12_Cap_interpolated_timesteps_step_2.txt
```

### Restore the original coordinate origin

Add the reference-point coordinates that were subtracted in Step 1:

```text
X_new = X + 9.12
Y_new = Y - 19.47
Z_new = Z + 19.46
```

This returns the coordinates to the original CFD coordinate system.

### Keep the velocity unchanged

The `U`, `V`, and `W` components remain unchanged.

### Save the final data

Save:

```text
13_Cap_interpolated_timesteps_step_3.txt
```

## Step 4 Final Result

The interpolated MRI velocity data are now expressed at the **original CFD inlet-cap coordinates**.

```text
Interpolated MRI velocities
          ↓
Reverse coordinate scaling
          ↓
Original MRI scale
          ↓
Reverse coordinate transformation
          ↓
Original CFD coordinate system
          ↓
Restore original CFD origin
          ↓
CFD inlet-cap coordinates + interpolated velocities
```

The velocity values remain unchanged throughout Step 4.

---

# Step 5. Boundary-Condition File Creation and Vector/Unit Correction

## Purpose

Step 5 converts the interpolated velocity data into the **BCT (`bct.dat`) boundary-condition format** used for the CFD simulation.

The BCT structure assigns a velocity history to every spatial point on the CFD inlet cap.

The general structure is:

```text
np nl

x1 y1 z1 nl nn
vx1 vy1 vz1 t1
vx2 vy2 vz2 t2
...
vxnl vynl vznl tnl

x2 y2 z2 nl nn
vx1 vy1 vz1 t1
...
```

where:

- `np` = number of spatial inlet points
- `nl` = number of temporal points
- `x, y, z` = inlet-point coordinates
- `nn` = mesh/node ID
- `vx, vy, vz` = velocity components
- `t` = time

Each spatial inlet point therefore has fixed coordinates and a corresponding velocity history throughout the cardiac cycle.

---

## 5.1 Extract the CFD Inlet Points

### Load the existing BCT file

Load the CFD-generated:

```text
bct.dat
```

This file provides the spatial points of the CFD inlet cap.

### Read the file structure

Read the first line to obtain the number of spatial points and temporal points.

### Extract the inlet-point information

For each spatial point, extract:

```text
X   Y   Z   number_of_timesteps   point_ID
```

Store the coordinates and point ID.

### Ignore the existing velocity data

The velocity data already present in `bct.dat` are not used.

Only the spatial points and point IDs are required as a reference for the new patient-specific boundary condition.

---

## 5.2 Create the Patient-Specific Boundary-Condition File

### Load the interpolated data

Load:

```text
13_Cap_interpolated_timesteps_step_3.txt
```

This file contains the MRI-derived velocity values at the CFD inlet-cap points for all timesteps.

### Match the spatial points

For each CFD inlet point, find the corresponding point in the interpolated data using its X, Y, and Z coordinates.

A small coordinate tolerance is used to account for numerical differences.

### Assign the velocity values

For every matched point, assign its interpolated:

```text
U   V   W
```

values for each timestep.

### Repeat for all timesteps

The same spatial points are retained throughout the cardiac cycle.

Only the velocity values change with time.

For the current workflow, the procedure uses **24 temporal points**.

### Handle unmatched points

If a CFD inlet point cannot be matched to the interpolated data, its velocity is set to:

```text
U = 0
V = 0
W = 0
```

This ensures that every inlet point has a velocity value at every timestep.

### Save the BCT-compatible file

Save:

```text
14_bc_interpolated.txt
```

**Result:**  
The interpolated MRI velocities have been placed into the BCT boundary-condition structure for all CFD inlet points and all 24 timesteps.

---

## 5.3 Convert the Velocity Units

### Load the BCT-compatible file

Load:

```text
14_bc_interpolated.txt
```

The velocity values are expressed in **m/s**.

### Convert to cm/s

Multiply each velocity component by 100:

```text
U_new = U × 100
V_new = V × 100
W_new = W × 100
```

Coordinates and time values remain unchanged.

### Save the converted file

Save:

```text
15_bc_interpolated_cm.txt
```

The velocity values are now expressed in **cm/s**.

---

## 5.4 Correct the Velocity Vector Direction

### Load the converted data

Load:

```text
15_bc_interpolated_cm.txt
```

### Apply the vector transformation

For every inlet point and timestep, apply:

```text
U_new = W
V_new = U
W_new = -V
```

This converts the velocity components to the required CFD vector convention.

### Keep the remaining data unchanged

The following remain unchanged:

- X, Y, Z coordinates
- point ID
- number of timesteps
- time values

Only the velocity components are transformed.

### Save the corrected file

Save:

```text
16_bc_interpolated_cm_corrected.txt
```

---

## 5.5 Final Result

The file:

```text
16_bc_interpolated_cm_corrected.txt
```

contains the complete patient-specific inlet velocity boundary condition with:

- all CFD inlet-cap points
- CFD point IDs
- velocity values for all 24 timesteps
- corresponding time values
- velocity in cm/s
- corrected velocity-vector convention

This file is ready to be used as the **time-dependent, patient-specific velocity inlet profile**.

---

# Step 6. Optional Temporal Interpolation

## Purpose

**Step 6 is optional.**

It is performed only when additional **temporal interpolation and smoothing** of the inlet velocity profile are desired.

The spatial inlet points do not change. Only the number of temporal points is increased.

In the current workflow, the original **24 temporal points** are interpolated to **201 temporal points** using cubic-spline interpolation.

The choice of **201 points is not a physical requirement**. It is used because it corresponds to the default temporal resolution of SimVascular. The number of temporal points can otherwise be selected according to the requirements of the CFD simulation.

---

## 6.1 Load the Corrected Boundary Condition

Load:

```text
16_bc_interpolated_cm_corrected.txt
```

This file contains the patient-specific velocity profile at all CFD inlet points for the original 24 temporal points.

---

## 6.2 Define the New Time Resolution

The cardiac cycle has a duration of:

```text
0.98 s
```

The new temporal array contains **201 equally spaced points** over:

```text
0 → 0.98 s
```

The beginning and end of the cardiac cycle remain unchanged.

---

## 6.3 Perform Temporal Interpolation

### Process each inlet point

Each spatial inlet point is processed independently.

Its coordinates and point ID remain unchanged.

### Read the original velocity history

For each inlet point, read the 24 original values of:

```text
U   V   W   time
```

### Apply cubic-spline interpolation

Create a cubic spline separately for:

```text
U(t)
V(t)
W(t)
```

and evaluate each spline at the 201 new temporal points.

This generates intermediate velocity values between the original temporal samples and provides a smoother temporal representation of the inlet profile.

### Repeat for all inlet points

Apply the same procedure to every spatial point on the CFD inlet cap.

The spatial velocity distribution remains unchanged; only the temporal resolution is increased.

---

## 6.4 Create the Interpolated Boundary-Condition File

### Update the number of temporal points

The file header is changed from 24 to 201 temporal points.

### Write the interpolated data

For every spatial point, write the 201 interpolated values:

```text
U   V   W   time
```

The spatial coordinates and point IDs remain unchanged.

### Save the final file

Save:

```text
17_bc_complete_interpolation_correction.txt
```

---

# Final Result

After completing the workflow, the 4D Flow MRI velocity data have been converted into a **patient-specific, time-dependent CFD inlet velocity boundary condition**.

The final profile contains:

- the CFD inlet-cap spatial points
- patient-specific velocity data derived from 4D Flow MRI
- velocity information throughout the cardiac cycle
- the original CFD coordinate system
- the required velocity units and vector convention
- optionally, increased temporal resolution for a smoother inlet profile

The complete workflow is:

```text
4D Flow MRI
     ↓
Step 1. Prepare CFD inlet-cap coordinates
     ↓
Step 2. Extract MRI velocity data within GOI selected to contain the inlet cap of interest
     ↓
Step 3. Spatially interpolate MRI velocities
     ↓
Step 4. Return coordinates to the CFD system
     ↓
Step 5. Create BCT boundary-condition file
     ↓
      ├── Unit conversion
      └── Vector correction
     ↓
Step 6. Optional temporal interpolation
     ↓
Patient-specific CFD inlet velocity profile
```

The **Supporting Files** folder contains the intermediate files generated throughout these steps. These files provide the required input and output between scripts and allow the complete workflow to be reproduced from the original MRI data to the final CFD inlet boundary condition.
